# Git Versioning, Tagging, and Release Rules

> Standard versioning approach for all Python projects using `setuptools_scm`.

---

## Version Format

- **Semantic Versioning**: `MAJOR.MINOR.PATCH` (e.g., `2.1.1`)
- **No `v` prefix**: Tags are `2.1.1` not `v2.1.1`
- **Dev versions**: Between tags, builds produce `X.Y.Z.dev0` (e.g., `2.1.2.dev0`)

---

## setuptools_scm Configuration

### pyproject.toml

```toml
[build-system]
requires = ["setuptools>=61.0", "wheel", "setuptools_scm>=8.0"]
build-backend = "setuptools.build_meta"

[project]
name = "package_name"
dynamic = ["version"]
# Do NOT include a hardcoded version field

[tool.setuptools_scm]
version_scheme = "guess-next-dev"
local_scheme = "no-local-version"
write_to = "package_name/_version.py"
write_to_template = '__version__ = "{version}"\n'
```

### Package __init__.py

```python
try:
    from package_name._version import __version__
except ImportError:
    __version__ = "0.0.0.dev0"

__all__ = ["__version__", ...]
```

### .gitignore

```gitignore
# Dynamic version file (generated by setuptools_scm)
package_name/_version.py
package_name.egg-info/
```

---

## Legacy Files

- **Delete `setup.py`** if it exists with hardcoded versions
- **Delete `setup.cfg`** version entries if present
- All version management goes through `pyproject.toml` + `setuptools_scm`

## Tagging Process

### Create a Release Tag

```bash
# Ensure you're on the correct branch with all changes committed
git tag X.Y.Z
git push origin branch-name
git push origin X.Y.Z
```

### Tag Naming Rules

| Correct | Incorrect |
|---------|-----------|
| `2.1.1` | `v2.1.1` |
| `1.0.0` | `V1.0.0` |
| `0.5.0` | `release-0.5.0` |

---

## Build Process

```bash
# Clean previous builds
rm -rf dist/ build/ package_name.egg-info

# Build
python -m build

# Verify
twine check dist/*
```

### Expected Output

| From Tag | Build Artifacts |
|----------|-----------------|
| `2.1.1` (exact) | `package-2.1.1.tar.gz`, `package-2.1.1-py3-none-any.whl` |
| After `2.1.1` | `package-2.1.2.dev0.tar.gz`, `package-2.1.2.dev0-py3-none-any.whl` |

## Pre-Commit CI Checks

Run these before creating any PR:

```bash
ruff check zebra_day tests
ruff format --check zebra_day tests
mypy zebra_day --ignore-missing-imports
```

Fix auto-fixable issues with `ruff check --fix .`

## GitHub Release Process

1. **Create tag locally** and push
2. **Create GitHub Release** via API or UI:
   - Tag: `X.Y.Z`
   - Title: `vX.Y.Z - Brief Description`
   - Body: Changelog with "What's New" section
3. **Optionally upload to PyPI**: `twine upload dist/*`

## Version Bumping Guidelines

| Change Type | Version Bump | Example |
|-------------|--------------|---------|
| Breaking API changes | MAJOR | `1.0.0` → `2.0.0` |
| New features (backward compatible) | MINOR | `2.0.0` → `2.1.0` |
| Bug fixes, patches | PATCH | `2.1.0` → `2.1.1` |

---

## Common Issues

| Issue | Solution |
|-------|----------|
| Build shows wrong version | Delete `setup.py`, clean `*.egg-info/`, rebuild |
| "version already set" warning | Remove hardcoded version from `setup.py` or `pyproject.toml` |
| `_version.py` not found at runtime | Install package with `pip install -e .` or build wheel |
| Tags not recognized | Ensure tags are pushed: `git push origin --tags` |
| Missing newline in `_version.py` | Add `\n` to `write_to_template` in pyproject.toml |
